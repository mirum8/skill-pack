# ASD-STE100 — the rules the page's prose follows

ASD-STE100 Simplified Technical English is a controlled language: a restricted vocabulary and a
small set of writing rules, made so that a reader — often one who reads English as a second
language — gets one meaning from each sentence on the first read. A review page is read exactly
that way: fast, beside the code, by people who did not write the change.

## Where it applies

All prose: the summary, the text of each concern, every "look closely here" reason, every
"not explained" reason, and the terminal reply.

It does **not** apply to code, hunk excerpts, identifiers, file paths, commit messages quoted from
the history, or a diagram label that is a code name. In STE terms those are **technical names**
and stay exactly as written — `OrderService.place()` is never "rewritten" into simpler words.

## Words

- Use words with one meaning, and use each word with that meaning only. "Check" means to examine,
  never a verification object.
- Prefer the approved simple word: *use*, not *utilize*; *do*, not *perform*; *start*, not
  *commence*; *before* / *after*, not *prior to* / *subsequent to*; *about*, not *approximately*;
  *make sure*, not *ensure*; *to*, not *in order to*; *through*, not *via*; *help*, not
  *facilitate*; *show*, not *demonstrate*.
- Technical names (classes, methods, fields, flags, tables, endpoints) and technical verbs of the
  domain (*compile*, *commit*, *merge*, *deploy*, *serialize*) are allowed.
- Keep one term for one thing across the whole page. If a section calls it "the cache", no other
  section calls it "the store".
- No noun cluster longer than three words: "the order retry limit", not "the order payment retry
  limit value". Break a longer one up with a preposition.

## Verbs

- Active voice: "`place()` now rejects an empty cart", not "an empty cart is now rejected".
  Passive only when the agent is unknown or does not matter.
- Simple tenses only: present for what the code does, past for what the old code did, future for
  what a call will do at run time. No "has been doing", "would have".
- No *-ing* form as a verb or a noun: "the method that parses the header", not "parsing the header
  happens in…".

## Sentences and paragraphs

- One topic per sentence. Descriptive sentences — almost all of this page — have **at most 25
  words**. An instruction to the reader ("Read the null check at …") has **at most 20**, and is in
  the imperative.
- Keep the articles (*the*, *a*); STE does not drop them to save words.
- A paragraph has one topic and **at most six sentences**. Prefer a vertical list when items are
  parallel.
- Say the condition first: "If the cart is empty, `place()` returns 400", not the reverse.

## Example

Not STE:

> This change basically refactors the order-placement flow so that validation is now being
> performed prior to the persistence step, which should ensure that invalid carts are no longer
> able to reach the repository layer.

STE:

> Validation now runs before the save. `OrderService.place()` calls `CartValidator.check()` first.
> If the cart is not valid, the method returns 400 and does not call `OrderRepository.save()`.
